# M8 Results

Date: 2026-06-29

## Summary

M8 MVP is implemented as an additive layer beside M7. It adds structured source-span contracts, deterministic hybrid retrieval, bounded repair attempts, dependency-aware status separation, M7-vs-M8 analytics, dashboard data providers/pages, an artifact-backed analytic chatbot, and release-check tooling.

M8 does not replace M7 verification. GIS remains verified-only.

## M8 Targets Not Yet Claimed As Measured

- Increase M8-loop-generated `repaired_successfully_count` above zero without increasing false verified count.
- Run M8 on Vancouver and Calgary after Burnaby stabilizes.
- Add richer table/branch-aware retrieval queries for missing-scope and missing-condition repair.
- Add browser-level dashboard interaction smoke checks for M8 pages.

## Remaining Risks

- Repair retrieval finds many plausible spans but does not yet generate verifier-winning candidate patches.
- M8 dependency status separation is useful but needs legal-review calibration before it becomes a release gate.
- Dashboard pages are modular and compile, but only data providers have automated tests.
- M8 chatbot is deterministic and artifact-backed; LLM wording can be layered later, but must stay bounded by these artifacts.
